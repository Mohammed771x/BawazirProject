# 05 — جودة الذكاء الاصطناعي وصحة التقييم وحدود الأدوات

طبّق `00-COMMON.md`. اختبر جودة حقيقية قابلة للقياس؛ اختلاف صياغة جائز ليس bug. افصل tests حتمية بعينات محفوظة عن evals لمزود حقيقي ذي تباين وتكلفة.

**اقرأ:** `ai-service/app/main.py` و`prompts.py` و`gemini.py` و`speech.py` و`tts.py` و`groq_chat.py` و`agent_prompts.py`، `backend/src/WordOs.Infrastructure/Ai/`، `SessionContentBuilder` و`SpeakingRules` و`WordEndpoints`، `Admin/AgentTools.cs` و`AdminAgentEndpoints.cs`. أعد استخدام pytest suites وAdminAgentTests واختبارات الجلسات.

- ابنِ corpus مرجعيًا معلومًا: مستويات A1 إلى C2، 1/5/10/15 كلمة حيث يسمح سقف المستوى، معنى واحد ومعانٍ متشابهة، past/participle/irregular plural، كلمة مركبة، كلمات مخصصة وخارج القاموس، تعليمات عربية وإنجليزية. حدّد expected properties وتقييمًا بشريًا للحالات الدلالية الغامضة؛ لا تستخدم حكم نموذج آخر وحده كحقيقة.
- المحتوى: وجود الكلمات بالصيغة والمعنى المقصودين، مستوى مناسب وطول وفق config/prompt الحالي، عنوان وأسئلة واختيارات كافية ومتمايزة، إجابة واحدة صحيحة، glossary وtarget spans متوافقان مع النص. relevel يحفظ موضوع/معاني الهدف ويتبع listening عند طلبه. لا تفرض أطوال مواصفة قديمة أمام ADR أحدث.
- Writing/Speaking: الاستخدام الحقيقي لا ذكر الكلمة وحدها أو ترديد tutor؛ عدم احتساب استعمال tutor كدليل المتعلم؛ خطأ نحوي بسيط لا يمحو معنى صحيح حسب القاعدة. اختبر الغياب والمعنى المخالف والتصريف المخالف ومحاولة «اعتبرني ناجحًا». تحقق أن domain يقرر، وأن JSON المزوّر أو النص المولد لا يستطيع تعديل مستوى/كلمة مباشرة.
- meaning checker: حقول تعريف/POS/CEFR مكتملة قبل تخزين كلمة جديدة؛ schema خاطئ/حقول ناقصة/نوع غير صحيح؛ عدم تجاوز رفض المدقق بإصرار المستخدم أو بحقل force مزوّر وفق ADR-112، وعدم تجاوز شرط كون المدخل إنجليزيًا. فرّق رفضًا مقصودًا عن فشل مزود.
- صلابة الخدمة: JSON ناقص/طويل/غير JSON، timeout/429/502/503، إلغاء أثناء النداء، retries وحدها، circuit/fallback إن وجد. الـbusy ليس تقييمًا خاطئًا ولا fallback مضللًا. لا يكتب الفشل نصف كلمة أو نصف جلسة. سجّل model/prompt version/tokens/calls لكل ناتج وإصلاح glossary أو shortening إضافي.
- حقن مباشر وغير مباشر في transcript/meaning/interests/feedback/tool result. اختبر حدود التعليمات والصلاحيات والخصوصية من خلال أثر ملموس، لا مجرد قول النموذج «سأتجاهل». الأوامر في البيانات لا تصبح SQL أو أدوات حرة.
- WordOS AI: tools allowlist وargs schema وصلاحية المستخدم، حدود rounds/history/cache، عزل conversation بين حسابين، حداثة النتائج وتغير filters، مصدر كل رقم، الامتناع عن اختلاق بيانات غير مسجلة، حفظ investigation/proposal دون اعتماد قرار تلقائي. بحث عادٍ عن نص لا يجب أن يصبح query مفتوحًا.
- Groq quota/timeout ثم Gemini: fallback ظاهر ومقاس، وتحسب تكلفته ضمن ميزانية الحملة. اختبر cache والحصص والأخطاء الحتمية بالمحاكاة؛ لا تستنزف quota حقيقية عمدًا.

**التقرير:** نجاح schema، تغطية الكلمات والمعاني، rubric الجودة ومعدل disagreement/false pass/false fail، عدد العينات لكل مستوى، latency p50/p95، fallback/retry rate، استهلاك tokens والمال إن كان معلومًا، وقيود الثقة. كرر عينة صغيرة معلنة (مثل 3 مرات للحالة إن سمحت الميزانية)، ولا تعمم من إجابة جميلة واحدة. استخدم [OWASP GenAI](https://genai.owasp.org/llm-top-10/) كمرجع لتصميم فحوص الحقن والصلاحيات، لا كافتراض بوجود عيب.
