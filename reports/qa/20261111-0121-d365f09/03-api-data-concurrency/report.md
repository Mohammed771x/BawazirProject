# 03 — عقود API وسلامة البيانات والتزامن

## 1. الخلاصة

- **الحملة:** `20261111-0121-d365f09` · النسخة HEAD `d365f09` · محلي، PostgreSQL 17.11 حقيقي بقاعدة مؤقتة من الـ migrations، و`ApiFactory` مع بدائل للذكاء الاصطناعي والبريد والساعة.
- **النتيجة:** **ظهرت عيوب مثبتة**، كلها في سباقات التزامن. العقود والتكرار المتتالي سليمة.
- **ما ثبت سليماً:**
  - التسجيل بالإيميل نفسه 10 مرات بنفس اللحظة ينشئ حساباً واحداً، والباقي يُرفض بلا 500.
  - إضافة نفس المعنى 10 مرات بنفس اللحظة تنشئ كلمة واحدة: `200x1, 409x9`، وحدث `Added` واحد.
  - نفس الإجابة 10 مرات تُسجَّل كمحاولة واحدة.
  - «إنهاء الجلسة» مرتين **متتاليتين** يرد بـ 409 ويُطبَّق مرة واحدة.
  - جهازان يغيّران الهدف اليومي يستقران على قيمة صالحة.
  - إعادة الإضافة بعد رد ضائع ترد بـ `409 WORD_ALREADY_ADDED` بلا تكرار.
- **ما لم يثبت:**
  - انقطاع الاتصال بالقاعدة أثناء `SaveChanges`.
  - الـ timeout الحقيقي على الشبكة (حاكيته بإعادة متتالية).
  - تطابق كل حقل بين C# وDart وTypeScript (راجعت `alreadyAdded` و`offset` فقط).
- **قرار النشر لهذا النطاق:** **لا مانع نشر مثبت.** فيه 4 عيوب تحتاج إصلاحاً غير مانع. الأثر الأساسي على **دقة القياس**، وهي هدف المنتج المعلن، لا على تقدم الطالب.

## 4. ملاحظات العقود

- `alreadyAdded` إضافي بقيمة افتراضية false في C# (`WordCandidateResponse`) وفي Dart (`?? false`). العميل القديم يتجاهله، والجديد مع خادم قديم يقرأه false. لا كسر.
- أخطاء الحدود (429) ترجع **بجسم فارغ** وبلا `Retry-After`، بخلاف شكل الخطأ الموحد `{error:{code,message}}`. العميل يترجم 429 بالكود (`http_wordos_api.dart:388`) فلا كسر. تفاصيل في 08.

## 6. إعادة التشغيل

```bash
cd backend && dotnet test tests/WordOs.Api.Tests --filter "FullyQualifiedName~Qa.ConcurrencyQaTests" --logger "console;verbosity=detailed"
```
`BurstAsync` يطلق الطلبات معاً من بوابة `TaskCompletionSource`. النتائج غير حتمية بطبيعتها، فالتكرار مذكور بصيغة x/n أعلاه.
